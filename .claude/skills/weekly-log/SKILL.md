# 주간 업무일지 작성

한 주치 일일 초안과 운영팀 시트 데이터를 모아 붙임2 주간 업무일지 양식을 채운다.

**역할 분담은 일일 일지와 같다.** 문서 생성(`fill_weekly_hwpx.py`)은 결정론적이므로 스크립트가
하고, 집계·문체는 판단이라 네가 한다. 셀 좌표를 직접 만지거나 hwpx XML을 손으로 편집하지 마라.

**이 양식이 일일 양식과 다른 점이 셋 있다. 셋 다 사고로 이어질 수 있으니 먼저 읽어라.**

1. **양식 파일이 빈 양식이 아니라 지난 주 제출본이다.** 출석률·진도율·이탈 위험 교육생 칸에
   지난 주 숫자와 **교육생 실명이 이미 들어 있다.** 이번 주 값으로 덮지 않으면 그대로 다시
   제출된다. `verify_weekly_hwpx.py`가 이걸 잡지만, 애초에 값을 받아 오는 게 네 일이다.
2. **일일 초안으로 채울 수 없는 칸이 있다.** 출석률·미션 진도율·이탈 위험 교육생은 디스코드나
   메모가 아니라 **운영팀 시트**에서 온다. 지어내지 말고 사용자에게 받아라.
3. **이 양식에는 「이번 주 잘한 점」 칸이 없다.** 월간일지에는 있지만 붙임2에는 없다.
   만들어 넣지 마라. 월간일지 블록이 필요하면 `/monthly-log`가 따로 만든다. **화면에 텍스트로만
   필요하면 `--values` 모드**(아래)를 쓴다 — 그때는 이 규칙이 적용되지 않는다.

## 인자

- `--date YYYY-MM-DD` — 그 날짜가 속한 주 (기본: 오늘)
- `--last-week` — 지난주
- `--redraft` — 이미 있는 `drafts/week-<월요일>.json`을 버리고 다시 만든다
- `--draft` — 3단계까지만 하고 멈춘다 (HWPX를 만들지 않는다)
- `--values` — HWPX를 만들지 않고 서술 5항목(잘한 점 포함)을 텍스트로만 출력한다. 아래
  "`--values` 모드" 절 참고
- `--no-upload` — 드라이브 업로드를 건너뛰고 `out/`까지만 만든다
- `--folder <URL 또는 ID>` — 이번 한 번만 다른 드라이브 폴더에 올린다

## `--values` 모드

붙임2 제출 파이프라인과는 별개의 조회용 출력이다. 사용자가 값만 보고 싶을 때 — 아직
운영팀 시트를 안 받았거나, 한글 파일이 필요 없을 때 — 쓴다. **`drafts/week-<월요일>.json`도
HWPX도 만들지 않는다.**

이 모드에서는 항목이 다섯 개다. 위 "다른 점 3번"의 「잘한 점 없음」 규칙은 여기 적용되지
않는다 — 붙임2 양식이 아니라 화면 출력이기 때문이다. 근거는 `/monthly-log`와 같다.

| 항목 | 근거 | 처리 |
|---|---|---|
| 이번 주 잘한 점 | `summary`, `counts`, `guidance_lines`, `counseling_lines` | 유도해서 채운다 |
| 이번 주 개선할 점 | 없음 | 후보만 제시하고 사용자에게 묻는다 |
| 교육생 관련 특이사항 및 이슈 | `counseling_lines`, `inquiry_lines` | 유도해서 채운다 |
| 운영진 공유 및 개선 필요사항 | `handover_lines` | 유도해서 채운다 |
| 다음 주 계획 | 없음 | 미결 건에서 후보만 뽑고 사용자에게 묻는다 |

절차:

1. 1단계(범위 결정, 일일 초안 수집)는 그대로 따르되 **운영팀 시트 데이터는 묻지 않는다** —
   출석률·진도율·이탈 위험 교육생은 이 다섯 항목에 없다.
2. 2단계의 판단 규칙(사안 단위 중복 제거, 민감 정보 익명화, `style/monthly.md` 문체)을
   그대로 따르되 분량 제한표는 적용하지 않는다 — 셀 높이 제약이 있는 문서가 아니다.
   잘한 점은 `style/monthly.md`의 "결과·반응은 근거가 있을 때만 붙인다" 규칙을 따른다.
3. 다섯 항목을 화면에 그대로 출력한다. 마크다운 장식을 두르지 않는다 — 사용자가 그대로
   복사해 쓸 수 있어야 한다 (`/monthly-log` 3단계 출력 형식과 같다).
4. 유도 불가 두 칸(개선할 점, 다음 주 계획)은 후보와 함께 한 번에 묻는다.
5. 파일을 쓰지 않는다. 6단계(문체 학습)는 그대로 적용한다 — 사용자가 문장을 고치면
   그 방향을 `style/monthly.md` 누적 규칙에 남긴다.

## 절차

### 1. 범위 결정과 입력 확보

대상 주의 월요일을 구한다. **작성 주간 표기는 월~일이고 일일 초안 집계는 월~금이다** —
양식이 월~일로 적게 되어 있어서 그렇고, 주말에는 초안이 없다.

#### 먼저 — 이미 만들어 둔 초안이 있는가

**`drafts/week-<월요일>.json`이 이미 있으면 다시 만들지 말고 그 파일로 3단계부터 이어간다.**
사용자가 손으로 고쳐 뒀을 수 있고, 운영팀 데이터를 이미 채워 뒀을 수도 있다.
다시 만드는 것은 `--redraft`가 있을 때뿐이고, 그때는 그렇게 하고 있다고 한 줄로 알린다.

#### 일일 초안 수집

월~금 5일의 `drafts/YYYY-MM-DD.json`을 읽는다. 있는 날과 없는 날을 한 줄로 보고하고,
빠진 날은 `/daily-log --date <날짜>`로 먼저 만들면 반영된다고 알려준다.
**없는 날을 지어내지 마라.** 초안이 0건이면 멈추고 알린다.

#### 운영팀 시트 데이터 확보

일일 초안에 없는 값이다. 아래를 **한 번에** 묻는다. 항목별로 나눠 캐묻지 마라.

```
주간일지에는 일일 일지에 없는 값이 셋 필요합니다. 운영팀 시트에서 확인해 주세요.

1. 출석률 — 20시간 이상 달성자 비율(%)과 출결률 평균(%)
2. 미션 진도율 — 구간별 인원 14칸
   0% / 9% / 18% / 27% / 36% / 45% / 54% / 63% / 72% / 81% / 90% / 100% / 시험 / TP
3. 학습 이탈 위험 교육생 — 인원수와 성명 (예: 3명 (홍길동, 김철수, 이영희))

표를 그대로 붙여넣으셔도 읽어내겠습니다.
```

**받지 못하면 그 값을 비워 두고 진행하되, 5단계 검사가 실패한다는 것을 알려라.**
추측한 숫자를 넣느니 검사에 걸려 멈추는 게 낫다. 지난 주 값이 맞다고 사용자가 확인해
준 경우에만 `--allow-stale`로 넘어간다.

#### author / team 확보

`config.toml`에서 읽는다. 없으면 일일 일지와 같은 방식으로 한 번 묻고 저장한다.

### 2. 판단 — 집계와 작성

`style/monthly.md`를 먼저 읽어라. 주간일지 서술 칸도 그 기준을 따른다 — 개조식이고,
`~했습니다` 체가 아니다. 누적 규칙이 기준선보다 우선한다.

**양식이 `- ` 글머리를 쓰므로 각 줄 앞에 `- `를 붙인다.** 이건 입력 원문의 마크다운을
옮기는 게 아니라 양식의 표기다.

서술 4칸을 채운다. 유도 가능한 것과 아닌 것의 구분은 `/monthly-log`와 같다.

| 칸 | 근거 | 처리 |
|---|---|---|
| 교육생 관련 특이사항 및 이슈 | `counseling_lines`, `inquiry_lines` | 유도해서 채운다 |
| 운영진 공유 및 개선 필요사항 | `handover_lines` | 유도해서 채운다 |
| **이번 주 개선할 점** | **없음** | 후보만 제시하고 사용자에게 묻는다 |
| **다음 주 계획** | **없음** | 미결 건에서 후보만 뽑고 사용자에게 묻는다 |

**중복 제거는 "사안" 단위다.** 며칠에 걸친 같은 건은 한 항목으로 묶는다.
상담·이탈처럼 민감한 건은 이름 대신 `교육생 1명`으로 쓴다. 다만 **이탈 위험 교육생 칸은
양식이 성명 기재를 요구하므로** 운영팀에게 받은 명단을 그대로 넣는다.

그다음 초안 JSON을 `drafts/week-<월요일>.json`에 쓴다:

```json
{
  "week_start": "2026-08-10",
  "author": "config.toml의 author",
  "team": "config.toml의 team",
  "attendance_rate": "58.8",
  "attendance_average": "20",
  "progress": [17, 9, 7, 6, 5, 0, 2, 0, 0, 0, 0, 0, 0, 0],
  "risk_students": "3명 (홍길동, 김철수, 이영희)",
  "improvement_lines": ["- ..."],
  "student_issue_lines": ["- ..."],
  "handover_lines": ["- ..."],
  "next_week_lines": ["- ..."]
}
```

운영팀 데이터를 못 받았으면 그 키를 **빼고** 쓴다. 0이나 빈 문자열로 채우지 마라 —
빈 값은 "0명"이라는 뜻이 되어 버린다.

#### 분량 제한

서술 4칸은 셀 높이가 고정이다. 넘치면 표가 밀린다. **한 줄은 한글 50자**이고(영숫자는 절반),
그보다 길면 다음 줄로 넘어가 두 줄을 먹는다.

| 칸 | 최대 줄 수 |
|---|---|
| 이번 주 개선할 점 | 5줄 |
| 교육생 관련 특이사항 및 이슈 | 7줄 |
| 운영진 공유 및 개선 필요사항 | 6줄 |
| 다음 주 계획 | 8줄 |

넘치면 항목을 지우지 말고 비슷한 것끼리 묶어라. `verify_weekly_hwpx.py`가 초과를 잡아내며
몇 줄을 줄여야 하는지 알려준다.

### 3. 초안 제시

초안을 표 형태로 화면에 보여준다. 파일 경로만 알려주고 끝내지 마라.
운영팀 데이터 3칸이 채워졌는지도 같이 보여준다 — 비어 있으면 그 사실을 눈에 띄게 알린다.

유도 불가 두 칸(개선할 점, 다음 주 계획)은 후보와 함께 한 번에 묻는다.

`--draft`면 여기서 멈추고 "확인 후 `/weekly-log`로 확정하세요"라고 안내한다.

### 4. 확인과 수정

사용자가 고쳐달라고 하면 `drafts/week-<월요일>.json`을 고치고 다시 보여준다.
승인할 때까지 반복한다.

### 5. HWPX 생성과 제출

```bash
python3 tools/fill_weekly_hwpx.py --in drafts/week-<월요일>.json
python3 tools/verify_weekly_hwpx.py "<위에서 출력된 경로>" --against drafts/week-<월요일>.json
python3 tools/upload_drive.py "<같은 경로>"
```

**`--out`을 주지 마라.** 제출용 파일명(`[코디세이]MMDD~MMDD_<이름>_퍼실리테이터_주간일지.hwpx`)은
운영팀이 요구하는 형식이라 스크립트가 초안에서 직접 만든다.

검사가 실패하면 초안을 고쳐 다시 만든다. **재시도는 2회까지다.** 두 번 고쳐도 통과하지
못하면 멈추고 검사기가 뭐라고 했는지 그대로 알린다.

- **잔존 검사가 실패하면 운영팀 데이터가 빠진 것이다.** 지난 주 값이 그대로 남아 있다는
  뜻이므로 사용자에게 값을 받아 다시 만든다. 지난 주 값이 맞다고 사용자가 확인한 경우에만
  `--allow-stale`을 붙인다. **네 판단으로 붙이지 마라 — 교육생 실명이 잘못 나갈 수 있다.**
- 검사를 통과한 뒤에만 올린다. `--no-upload`가 있으면 업로드를 건너뛴다.
- 업로드가 실패하면 그 작업은 실패다. 파일 경로만 보여주고 끝내지 마라.

### 6. 문체 학습

사용자가 4단계에서 문장을 고쳤다면, 그 교정의 **방향**을 규칙으로 뽑아 `style/monthly.md`의
"누적 규칙"에 날짜와 함께 추가한다. 교정이 없었으면 아무것도 추가하지 마라.

## 하지 말 것

- 출석률·진도율·이탈 위험 교육생을 추측으로 채우기 — 운영팀 시트에서만 온다
- 운영팀 데이터를 못 받았는데 `--allow-stale`로 넘어가기 — 지난 주 교육생 실명이 그대로 제출된다
- 「이번 주 잘한 점」을 붙임2 초안(`drafts/week-<월요일>.json`)이나 HWPX에 넣기 — 이 양식에
  없는 항목이다. `--values` 모드의 화면 출력에만 넣는다
- 개선할 점 / 다음 주 계획을 사용자 확인 없이 확정하기
- 초안이 없는 날을 추측으로 메우기
- `~했습니다` 체로 쓰기 — 서술 칸은 개조식이다
- 이미 있는 `drafts/week-<월요일>.json`을 말없이 덮어쓰기
- 검사에 실패한 파일을 드라이브에 올리기
- 양식 파일(`templates/weekly.signed.hwpx`)을 git에 추가하기 — 서명과 교육생 실명이 들어 있다
