# 일일 업무일지 문체 가이드

초안에서 유일하게 치명적인 오류는 **문체·톤**이다. 건수나 분류가 조금 어긋나는 건 확인 단계에서
바로잡으면 되지만, 말투가 어긋나면 전체를 다시 써야 한다. 그래서 이 파일이 품질의 중심이다.

작성 시점에 참조할 과거 일지가 없었으므로, 아래 기준선은 양식 자체의 안내문구 톤에서 출발한다.
**운용하면서 사용자가 초안을 고칠 때마다 그 교정 방향을 규칙으로 여기에 추가한다.**
규칙이 쌓일수록 고칠 일이 줄어드는 것이 이 시스템의 성공 지표다(AC-10).

---

## 기준선 (초기값)

### 어미와 격식
- `~했습니다` 체로 통일한다. `~함`, `~했음` 같은 개조식이나 `~했다` 체를 섞지 않는다.
- 한 항목은 한두 문장으로 끝낸다. 길어지면 항목을 나눈다.

### 관점
- 주어는 작성자 본인이다. 다만 "제가"를 반복해 쓰지 않고 자연스럽게 생략한다.
- 교육생은 관찰 대상이지 평가 대상이 아니다. 사실과 조치를 쓰고 인물평은 쓰지 않는다.
  - 나쁨: 의지가 부족한 교육생이 있었습니다.
  - 좋음: 출석이 2주 연속 불규칙한 인원이 1명 있어 개별 면담을 진행했습니다.

### 금지
- 대화체와 구어: `~인 것 같아요`, `~네요`, `ㅎㅎ`, 이모지
- AI 티 나는 상투구: `~에 대한 논의가 활발히 이루어졌습니다`, `성공적으로 완료하였습니다`,
  `적극적으로 지원하였습니다` 같은 내용 없는 수식
- 근거 없는 정도 부사: `매우`, `상당히`, `굉장히`
- 디스코드 원문 인용부호나 마크다운 기호(`>`, `**`, 백틱)를 그대로 옮기는 것

### 사실 처리
- 디스코드에 없는 내용을 지어내지 않는다. 근거가 약하면 항목을 만들지 않는다.
- 건수는 실제 수집된 건수와 일치해야 한다. 반올림하거나 보기 좋게 맞추지 않는다.
- 해당 내역이 없으면 억지로 채우지 말고 `해당 없음`이라고 쓴다.
- 교육생 이름·닉네임은 그대로 적어도 된다(내부 제출 문서). 다만 상담 내용처럼 민감한
  항목은 이름 대신 `교육생 1명`처럼 익명으로 쓰는 편이 자연스럽다.

### 항목 형식
양식이 쓰는 대괄호 라벨을 유지한다.

```
[문의 1] 가상환경 활성화 시 명령을 찾을 수 없다는 오류 문의
조치 내용: 셸별 활성화 경로 차이를 안내하고 재생성 절차를 공유했습니다.
```

- 문의 상세: `[문의 N]` 다음 줄에 `조치 내용:`
- 상담 상세: `[상담 내용 N]` / `[참여 독려 N]`
- 학습 지도: `[학습 지도 N]` 다음 줄에 `가이드 내용:`

### 오늘 업무 요약 (r3c1)
- **반드시 한 문장.** 마침표는 하나만 찍는다.
- 분위기 한 조각 + 그날의 핵심 이슈 한 조각을 붙인다.
- 예: `전반적으로 학습 분위기는 안정적이었으나 파이썬 가상환경 설정 문의가 반복되어 별도 안내가 필요합니다.`
